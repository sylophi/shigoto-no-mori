# v3: the great refactoring

The charter and checklist of the `v3` branch. Every PR against `v3`
names the step it closes and ticks its box here. The branch merges
`main` every few days. This file goes when `v3` merges into `main`.

Written 2026-10-07 from the planning threads listed at the end. Where
a number or a claim below matters to a decision, it was measured or
checked on that day; re-measure before relying on it months later.

## Why

v3 changes how the codebase is built, not what the product does. In
order: development velocity, robustness, and less to hold in one head.
Line count is not the metric. One person and their agents holding the
whole thing in their head is.

Two premises. Everyone working here knows the libraries introduced
below, so their learning cost is not an argument. And YAGNI applies to
implementations, never to requirements (`PRODUCT.md`): nothing the
product does gets trimmed to make the build smaller.

What the audits found, in one line each: the code is lean (0.08% copy
paste, about 4.5k cuttable lines in 177k), the same knowledge lives in
several hand-synced places in two languages, the hard bugs come from
lifetimes, cancellation and errors crossing process and device
boundaries, and the rules for those live in comments (20% of all
lines) rather than in anything the compiler checks. The architecture
scored 8 of 10; its weak spots are five orchestrators near 1,000 lines,
three hand-rolled wire loops, results trusted unvalidated on the
client, and a hub version floor that the comments promise and no code
implements.

## Decisions

Settled with the owner. Each one says why, so a later PR does not
relitigate it.

1. **Effect, all the way, in every TypeScript package.** Services and
   Layers in place of impl slots and global setters, one layer graph
   per subsystem under a scoped runtime, Schema in place of zod, tagged
   errors end to end, Effect RPC in place of the hand-rolled socket,
   and Schedule, Stream, Semaphore and Cache in place of the
   supervisor, heartbeat, watchers, limiter, singleFlight and ttlCache.
   Half-Effect is the worst outcome: two error models, two ways to own
   a lifetime, and a seam between them everywhere. Effect 4 went stable
   on 2026-10-01; its `Schema`, `rpc`, `socket`, `process`, `cli`,
   `http` and `sql` modules are still marked `@stability unstable`, so
   every Effect package is pinned to one exact version and bumped in
   its own PR. Effect itself is never patched; a gap is wrapped on our
   side.
2. **The Go CLI becomes a TypeScript engine package.** Projects,
   worktrees, state, config, git, clone checkout, land and merge,
   doctor, names, launchers, package scripts, the updater: one
   implementation, written once as Effect services, imported directly
   by the host and wired to commands by a thin terminal entrypoint.
   This deletes `cliDelegate.ts`, `cliRunner.ts`, the Go struct twins
   of every zod schema, the mirrored utilities, and the parity proofs.
   It is the single biggest simplification available: two codebases
   become one language. `file-sync/` stays Go because it embeds
   Mutagen.
3. **The terminal `sm` is a Bun-compiled binary.** Measured on a
   trivial script, warm: Go 4.5 ms, Bun compiled and ad hoc signed
   18 ms, a Node single executable 23 ms, plain node 24 ms, Electron as
   node 85 to 95 ms. Bun is the easiest to build and ship and keeps the
   `RunAsNode` fuse off. Two rules keep it safe: the engine uses Node
   APIs only, never Bun globals, and CI runs the CLI proofs against
   the compiled binary, not only the source under vitest. Electron as
   node was rejected: it needs the fuse on, costs 7x startup on every
   shell open, and reworks the updater.
4. **macOS syscalls go in a small Go helper, not a native addon.** Node
   cannot `clonefile` a tree, read or set `st_flags`, list or strip
   xattrs, read APFS private size through `getattrlist`, or name the
   filesystem type. A helper bundled like `file-sync`, lifting the
   existing `clone_darwin.go` and `diskusage_darwin.go` code, exposes
   those five verbs. It batches: a verifier asks for the flags and
   xattrs of a whole tree in one call that streams results, never one
   spawn per file. Nothing in the engine is native, so Bun and Node
   behave identically.
5. **One SQLite store in place of JSON files with locks.** The
   registry, project configs, marks and state, plus the mirror
   registry, script persistence, mirror history, ports and the device
   id are hand-rolled JSON persistence today, with two writers, a lock
   protocol, atomic renames, file watchers and echo suppression. SQLite
   in WAL mode is the boring mechanism for two processes sharing
   state: writers serialize, readers never block, a relocate is one
   transaction, migrations are code, and change detection is a cheap
   data-version check. The engine codes against Effect's `SqlClient`
   with the node sqlite driver in the host and the bun one in the CLI
   (confirm the driver package names at 4.0.1 when step 2 starts; T3
   uses the Durable Object one). v3 imports the JSON once. `sm --json`
   covers what hand-reading the files did.
6. **The host runs as its own process, and the local machine is just
   another device.** After step 4 the renderer reaches a host over
   Effect RPC on a socket. The host moves into an Electron utility
   process serving that socket on loopback, so the desktop renderer,
   the web client and remote devices use one path. The Electron IPC
   bridge, the preload transport, the web loopback binding, the
   local-host gating and the two parallel composition roots go.
   Electron main keeps window, menu, dialogs, tray, keychain and
   updater. Host work can no longer stall the window, a host crash is
   a reconnect, and `sm serve` on a box with no screen falls out. The
   overhead is one process of roughly 60 MB and a startup that
   overlaps with the window loading; a loopback call costs tenths of a
   millisecond, which every remote device already pays. If it ever
   shows in a profile, Effect RPC also runs over a MessagePort handed
   to the renderer with the same contracts.
7. **Streams in place of invalidation.** The host exposes each view as
   a stream (the worktrees of a project, mirrors, script runs) and the
   renderer subscribes. The query-key registry, the remote-viewer cache
   ping, the `movesHostState` flag and the push handlers that write
   into the cache disappear. A database commit becomes a host stream,
   which becomes an RPC stream, which becomes an atom.
8. **Renderer: views and containers.** Every component is one of two
   things. A view takes data and callbacks and only draws. A container
   binds data to a view and has no markup of its own. With atom-react a
   container is a few atom subscriptions. The marketing site renders
   the same views over fixture scenes at build time and hydrates the
   real containers over a fixture-backed host layer for the live
   frames, which is what the lab's fake host does today in an iframe.
   `@effect/atom-react` replaces React Query (64 call sites) and the
   `useSyncExternalStore` stores (12 files), decided at a go/no-go
   after step 4 when the streams exist to feed it.
9. **Real workspace packages.** `contracts`, `engine`, `host`, `ui`,
   `desktop`, `web`, `cli`, `hub`, `marketing`, one pnpm workspace at
   the root, one catalog pinning each dependency once. A package that
   does not depend on `electron` cannot import it, so the boundary
   proof becomes the dependency graph. The single-project layout came
   from the Go split; the marketing PR hit it a second time (two
   Reacts, install ordering, a CSS rewrite plugin), and packages remove
   all three.
10. **Vitest for the proofs, before any Effect code.** It replaces the
    custom runner, the harness half of `checkKit`, and the per-proof
    lefthook globs with `vitest related`. The hub already runs vitest.
    Forks pool, no file parallelism, since proofs spawn real git. It
    changes how every later PR is tested, so it goes first, not in the
    middle.
11. **The wire break is what makes it 3.0.** Effect RPC between devices
    and to the hub replaces the custom framing. The hub gets a real
    version floor (promised in comments today, implemented nowhere),
    the production hub and the web client flip together at 3.0.0, and
    a v2 device gets a clear "update required". v3 requires passing
    through the last v2 release first, and every pre-v3 migration is
    deleted.
12. **`hue.go` is dropped.** It only colours project names in CLI
    listings, the app never uses it, and a port needs image decoders.
13. **The CLI's surface is frozen.** Verbs, flags and the JSON output
    stay as they are through the port, so `skills/` and shell habits
    never change. The parity harness against the Go `sm --json` is
    that contract. The Go `sm` stays the shipped binary until the
    switch-over PR.
14. **`main` keeps moving.** No feature slows down for v3. The branch
    merges `main` every few days and pays the cost of re-doing a
    landed feature against refactored code when it happens.
15. **An early go/no-go.** When the first Effect subsystem (step 3) and
    the first engine slice (step 2) land, the owner reads both and
    decides the code is something they want to hold in their head,
    before the other hundred-plus PRs.
16. **Ordinary PR titles.** No step-and-slice naming. This checklist
    tracks which step a PR closes.

## Process

Same mechanics as v2, which took 99 PRs over 25 days with 8 merges from
`main`, two test prereleases and one rc. Expect two to three times
that.

- `v3` is cut from `main`. PRs target `v3`, one worktree per PR,
  finalized and reviewed like any other PR.
- `main` is merged into `v3` every few days; conflicts are resolved on
  `v3`, never by rebasing `v3`.
- Prereleases `v3.0.0-test.*` are cut from the branch (the release
  workflow signs prereleases from any branch; a full release must be on
  `main`). They point at the dev hub until cutover and are dogfooded on
  every device.
- Before the rc: a code-quality review pass, a remote-feature pass and
  a security audit, as v2 did (#272, #281, #285, #305).
- `v3.0.0-rc.1`, then one merge into `main` and the `v3.0.0` tag. The
  production hub and the web client deploy with it.
- Effect installs clear the 7-day package cooldown on 2026-10-08 for
  4.0.0 and 2026-10-12 for 4.0.1. Step 0 needs neither.

## Steps

Steps 2 and 3 run in parallel in separate threads after step 1. Step
4 needs 3 and the engine's control client from 2. Step 5 needs 4's
protocol. Step 6 needs 4.

### Step 0: groundwork

- [x] Cut `v3` and commit this file.
- [ ] `EFFECT.md` at the root: the conventions, written before any
      Effect code lands. Start from T3's `effect-services.md`
      (where a feature lives; the shape of a service module; runtime
      boundaries; errors) and add: lifetimes (`Layer.scoped` and
      `acquireRelease` in place of `stop()` latches), concurrency (when
      a Stream, Queue or PubSub, `Schedule` for anything that retries),
      node builtins (Effect's `FileSystem`, `Path` and `process`
      services, never `node:fs` in a service), contracts (Schema, and
      the `remote`, `gated`, `invitable`, `movesHostState`,
      `tracksProjectUsage` and `grant` annotations), tests (test layers
      for external dependencies only, `TestClock`, never mock the
      logic under test), and the views-and-containers rule for the
      renderer (in `DESIGN.md`, next to "one component tree").
- [ ] `PRODUCT.md`: the "boring, conventional mechanism" line names
      Effect as the house mechanism, so it is not cited against every
      Effect PR. `AGENTS.md` points at `EFFECT.md` and this file.
- [ ] Workspace packages: the pnpm workspace at the root, the catalog,
      `contracts`, `engine`, `host`, `ui`, `desktop`, `web`, `cli`,
      `hub`, `marketing`. Scaffold first, move code as the steps reach
      it. The root stops forwarding scripts.
- [ ] Vitest for the proofs (decision 10). Land #501 first; its CI job
      is the safety net, and its proof selection is replaced here.
- [ ] Tooling: `@effect/tsgo` for typecheck with Effect diagnostics,
      custom oxlint rules in `lint/` (namespace imports from subpaths,
      no runtime inside a service, no node builtins inside a service,
      every disabled diagnostic says why), `knip` for dead exports.
- [x] `electron-log` for a real log file in `~/Library/Logs`; the
      111 `console.*` calls in main, host and shared go nowhere today
      when the app is launched from Finder.
- [ ] Bug fixes that belong on `main` now, not on the branch: the
      socket server re-adding a mid-handshake connection after stop,
      the palette mirror badge with device icons off (unverified), and
      the second audit round's bugs (handed to the bug thread).

### Step 1: contracts

- [ ] zod to Schema across `shared/schemas`, keeping the JSON on the
      wire byte-identical. 88 files import zod today.
- [ ] `Schema.TaggedError` end to end. The renderer stops matching
      message prefixes (`shared/errors.ts`).
- [ ] The contract's per-call flags become annotations on RPC groups,
      one per module (33 modules). The renderer's API object and the
      `HostApi` type are generated from the contract, retiring the
      triple listing in `client.ts` and the 140-line source-parsing
      test. A `grant` annotation ties the consent text to the calls it
      covers.
- [ ] Results are validated on the client for remote invokes and
      pushes (today only the server checks outputs, and only in dev).
- [ ] Protocol version in the contract and a golden encoded fixture
      per RPC that must still decode, so two 3.x builds cannot drift.
- [ ] Hub protocol to Schema.

### Step 2: the engine

The Go CLI becomes `engine/`: pure Node TypeScript, Effect services, no
Electron import, enforced by the package graph. The Go `sm` stays the
shipped binary until the last box.

- [ ] Scaffold, the SQLite store (decision 5) and its migrator, the
      one-time import from the JSON files.
- [ ] Data model services: paths, registry and state, identity,
      layout, config keys and defaults from a single Schema (closes the
      "setting that cannot be turned off" class for good), names,
      launcher catalog, package scripts.
- [ ] One `Git` service, merging `gitx.go` and `host/lib/git`.
- [ ] The parity harness: the Go `sm --json` and the engine run against
      the same sandboxes and are diffed verb by verb. The `cli-reads`
      and `identity` proofs become this harness.
- [ ] The Go helper for the five darwin syscalls (decision 4), built
      and bundled like `file-sync`.
- [ ] Worktrees: list, status, create, rm, relocate, reorder, marks.
      Clone checkout, carry-over and verification, with the
      differential fuzz test ported (seeded random trees against `git
      worktree add`). Hygiene and disk usage as async walkers.
- [ ] Land, merge, stack, PR, done, doctor, transfer, shelf, shell
      integration, `sm run` as a signal-forwarding child (Node cannot
      exec over itself), and the updater, which gains the tests it
      never had (`verifySignedUpdate`, `swapBundle`,
      `installedBundlePath`, `--finish-install`).
- [ ] Schema-derived arbitraries with fast-check for the parsers and
      the layout math.
- [ ] The terminal entrypoint on `effect/cli`, built with
      `bun build --compile`, ad hoc signed in dev and properly signed in
      the release. Menu and picker on ink. Commands return typed
      errors; the exit code derives from the error, which ends the
      hand-written exit codes (and the 1-versus-2 mistakes).
- [ ] Switch-over, one PR: the host imports the engine; `cliDelegate`,
      `cliRunner`, `lockFile.ts`, `jsonFile.ts` and the paths mirror
      go; `cli/` is deleted; the four "a CLI child exists" mechanisms
      (watcher echo suppression, the busy and quit prompt,
      `killAllCli`, `noteSelfWrite`) get explicit equivalents; the
      license generator and the dev loop drop the Go build for the CLI;
      `cliInstall` links the compiled binary.

### Step 3: the app core

Main and host to Effect, subsystem by subsystem, each behind its
existing Promise interface until its callers move.

- [ ] Runtime and lifetimes: one layer graph, `Scope` finalizers in
      place of the quit chain in `main/index.ts`, the per-subsystem
      `stop()` latches and the 15-second `app.exit` backstop.
- [ ] Processes through `effect/process`: cloudflared, the file-sync
      daemon, pty scripts behind a node-pty wrapper, git and gh. Move
      steps undo themselves with finalizers. The pid file for orphans
      stays, since a scope cannot help after a crash.
- [ ] `Schedule` for reconnects and heartbeat, `Stream` for the git
      and state watchers (`FileSystem.watch` plus `debounce` in place
      of `coalesce` and about ten hand-written debounces), `Semaphore`
      and `Cache` for `limit`, `singleFlight` and `ttlCache`,
      `TestClock` for `fakeClock`.
- [ ] `Logger` and `Tracer` for the console calls and `logFailure`,
      electron-log as the file sink, a local trace file per device so
      one move can be followed across the app, the host and the peer.
      `effect/devtools` in dev.
- [ ] `Config` for the env reads, `KeyValueStore` for electron-store.
- [ ] While each file is open: split the five large orchestrators
      (`socket/server.ts` 1,047 lines, `modules/sync.ts` 1,020,
      `modules/control.ts` 1,005, `mirror/gitFollow.ts` 953,
      `modules/mirror.ts` 760) into planner, executor and wire adapter;
      merge the desktop and web account handlers; one mirror mode field
      in place of three flags; one connection record in the socket
      server; `util.parseEnv` for the hand-written dotenv parser; one
      timeout-or-fallback helper in control; one peer-client seam.

### Step 4: transport

The 3.0 wire break.

- [ ] Effect RPC over Effect's socket for the device link, replacing
      `host/socket/server.ts`, `wsClientTransport.ts`, `channels.ts`,
      `frames.ts`, `heartbeat.ts` and `proof.ts` (about 1,800 lines
      plus the credit flow). Middleware carries the ticket handshake,
      the command gate and tracing. Request interruption retires the
      `moves.ts` cancel registry, the per-page `AbortController`
      rotation and the `HandlerContext.signal` plumbing (57 uses).
      Streaming RPCs replace broadcasts and listener sets. Pull-based
      backpressure replaces the credit flow.
- [ ] The host as a utility process on loopback (decision 6). The
      Electron IPC bridge, the preload transport and the web loopback
      binding are deleted rather than converted.
- [ ] The CLI control wire uses the same RPC client from the engine's
      terminal entrypoint, so three wire loops become one.
- [ ] Streams in place of invalidation (decision 7) on the host side:
      each view a stream from the store's change notifications.

### Step 5: the hub

- [ ] Routes on `effect/http-api` with a typed client, the shared
      Schema protocol, Durable Object storage through Effect's sqlite
      driver, the Worker calling its object directly instead of through
      internal fetch routes, the unreachable revoked-table fallback
      removed.
- [ ] The version floor enforced: a v2 device is turned away with a
      clear message. Dev hub during the branch, production at cutover.

### Step 6: the renderer

- [ ] Views and containers (decision 8), first, before atom-react.
      The closed PR #461's head commit is the reference for the split
      (56 views, 8 scenes, a `scenes` proof that renders every view in
      Node); not a cherry-pick, `main` has moved under it.
- [ ] The `ui` package: views, primitives, the stylesheets. Theme
      classes scoped to the app's root element instead of `<html>`, the
      phone layout on container queries, no globals (`window.api`
      becomes the RPC client provided through the runtime).
- [ ] Data layer onto the RPC client on one managed runtime, React
      Query untouched. Then the go/no-go: `@effect/atom-react` with
      reactivity keys in place of manual invalidation.
- [ ] UI library adoptions: Base UI `Dialog` behind `ModalShell` (focus
      trapping and return for the 13 dialogs; `dom.ts` admits none of
      them trap focus today), Tabs and RadioGroup for `useRovingPick`
      and the segmented control, the router's match hook for
      `routePaths`, `electron-context-menu` for `contextMenu.ts`.
- [ ] One settings form for every device, one transfer-actions
      component for both directions, one tone table, the class strings
      and plurals the audit listed.
- [ ] The marketing site: one fixture world shared by the lab, the
      scenes and the site; build-time views; live frames hydrated over
      a fixture-backed host layer; `og.jpg` shot from the hero scene in
      CI.

### Step 7: sweep and ship

- [ ] Delete every pre-v3 migration (legacy mirror cleanup,
      `adoptLegacyGrant`, the default-name migration,
      `dropRemovedLanKeys`, `state.json` to `registry.json`).
- [ ] `pnpm licenses list` in place of `license-checker`.
- [ ] Shared fakes and sandboxes for the direct-plane, sync and mirror
      proofs; the fuller golden file in place of `socket-host`'s
      spot-checks.
- [ ] A comment pass: the ordering and cleanup prose that the
      structure now enforces goes; the drifted comments (the version
      floor, fields by old names) get fixed.
- [ ] The three review passes, the `v3.0.0-test.*` prereleases on every
      device, `v3.0.0-rc.1`, merge, tag.

## Measurements and facts

Lines on 2026-10-07: main 8.3k, host 20.7k, shared 16k, renderer 62k,
web 1.2k, proofs 23k, lab 3.9k, hub 3.5k, cli 22k plus 11.5k of
tests, file-sync 1.6k. Remote code is about a third of the repo and
about half of the app backend. Tests are 21% of the repo.

Counts the plan replaces: 111 `console.*` calls, 57 `AbortSignal` and
`AbortController` uses, 10 `process.env` reads, 88 files importing
zod, 64 React Query call sites, 12 store files, 49 proofs, 57 lefthook
jobs, 39 Go test files. Of 104 commits touching `cli/`, 22 also had to
touch the TS side.

Versions on 2026-10-07: effect 4.0.1 (2026-10-05), @effect/vitest,
@effect/platform-node, @effect/platform-bun and @effect/atom-react
4.0.1, @effect/tsgo 0.51.0, vitest 5.0.3, knip 6.40.0, Node 24.15,
Electron 43.1 with Node 24.18, Bun 1.4.0, Go 1.26.5.

T3 Code is the reference for the shape: Effect services in
`apps/server`, the conventions in `docs/internals/effect-services.md`,
five custom oxlint rules, a Node single executable for its CLI, and
`@effect/atom-react` for its web data layer. Its mistakes to avoid:
conventions written after the code (about 30 cleanup PRs), one giant
layer graph (`server.ts` 1,077 lines, `ws.ts` 3,200), the node-builtin
diagnostic left on without a plan (281 suppressions), and patches kept
against Effect.

## Risks

- Effect's unstable modules will have breaking minor releases. Pin
  exact versions; upgrades are their own PRs.
- Clone checkout and the updater are the two places where a port can
  lose data or brick an install. Let the parity harness and the
  differential fuzz test run long there.
- The wire break strands any device not updated through the last v2.
  The version floor makes that explicit instead of silent.
- Simple code gets a little wordier under Effect and debugging through
  fibers is less direct than plain async stacks. The tracer and the
  conventions are the answer; the go/no-go (decision 15) is the check.

## Left alone

Electron, React and the renderer's UI libraries; the three remote
mechanisms (port forwarding, mirroring, transfer); Mutagen in
`file-sync`; cloudflared; Clerk; the hub on Cloudflare; the villagers.
Effect's `workflow`, `eventlog`, `sql` in the app, `cluster` and `ai`
are out. zustand or jotai, form and hotkey libraries, simple-git or
isomorphic-git, Octokit, electron-updater and @parcel/watcher were
considered and rejected. `semver` and `proper-lockfile` were rejected
only because they would disagree with the Go CLI; after step 2 they
are fair game.

# contracts

Shared definitions for everything that crosses a wire or sits on disk, defined once for every side: the app's main process, host, renderer, and web client.

- [`src/schemas/`](src/schemas/): data shapes defined with Effect Schema, with `strict` and `loose` for contract payloads and [`index.ts`](src/schemas/index.ts) as their barrel.
- [`src/modules/`](src/modules/): one contract per module, expressed as an `RpcGroup` of the calls and pushes each side serves. Each entry is tagged with its channel and classified by annotations ([`src/contract.ts`](src/contract.ts)). [`src/grants.ts`](src/grants.ts) defines the consent lines referenced by remote gated calls, and [`src/types.ts`](src/types.ts) derives client and handler types from the groups.
- [`src/hubProtocol.ts`](src/hubProtocol.ts): the account's device representation shown by the app (`DeviceInfo`) and its id.
- [`src/errors.ts`](src/errors.ts): the typed errors declared by contracts and recognized by the renderer, including the hub's refusals of this device, which cross every wire unchanged as their own types.
- Host-scoped modules are implemented by handler maps in `app/host/ipc/modules/<module>.ts`, which [`app/host/process/handlers.ts`](../../app/host/process/handlers.ts) combines into the layer served by the host's listeners. Client-scoped modules are served by the shell ([`app/main/ipc/modules/`](../../app/main/ipc/modules/)). Call annotations declare who may call each RPC, and `defineContract` throws at module load time if a host call omits a required annotation:
  - `remote` (required on every host invoke or view): `true` only when a peer may call it. Loopback-only modules can set it once at the module level as `{ scope: "host", remote: false }`.
  - `gated` (required on every remote call): `true` for anything that changes what the user owns, plus the reads listed in [`src/contract.ts`](src/contract.ts).
  - `grant` (required on every remote gated call): names the covering consent line from [`src/grants.ts`](src/grants.ts).
  - `tracksProjectUsage` and `busy` (what an app quit waits on the call for): opt-in, and [`src/contract.ts`](src/contract.ts) documents when to use them.
- [`src/link.ts`](src/link.ts): the device link's `RpcGroup`, combining every module's remote calls with the link's own calls ([`src/modules/link.ts`](src/modules/link.ts)), along with the middleware tags that guard it. [`src/allModules.ts`](src/allModules.ts) lists the modules included in it, and `ChannelRefusedError` ([`src/errors.ts`](src/errors.ts)) defines the reasons opening a byte channel can be refused.
- [`src/sharedSettings.ts`](src/sharedSettings.ts), [`src/leaveOutRule.ts`](src/leaveOutRule.ts), [`src/pullRequestStack.ts`](src/pullRequestStack.ts), [`src/releaseVersions.ts`](src/releaseVersions.ts), [`src/accountServiceConfig.ts`](src/accountServiceConfig.ts): pure functions over the schemas for rules that both sides must apply identically (merging shared settings, a mirror's leave-out rule, stacked pull requests, release precedence and the changelog, and the account's build configuration).
- [`src/predicates/`](src/predicates/), [`src/deviceIcon.ts`](src/deviceIcon.ts), [`src/platform.ts`](src/platform.ts), [`src/mirrorIgnores.ts`](src/mirrorIgnores.ts): shared constants and validation checks used both to build schemas and directly by the app.
- [`src/git/`](src/git/) (branch names, matching git's ignored paths, worktree layout paths), [`src/projectPaths.ts`](src/projectPaths.ts), [`src/scriptEnv.ts`](src/scriptEnv.ts), [`src/lifecycleScripts.ts`](src/lifecycleScripts.ts) (what a lifecycle slot runs), [`src/typedLines.ts`](src/typedLines.ts) (what the app types into a terminal, formatted for its shell's syntax), and [`src/mediaTypes.ts`](src/mediaTypes.ts): pure helpers shared by both the host and views, placed here because every side can compile the contracts package and nothing else.

Consumers import modules by their path under `src/` without a file extension, such as `@shigomori/contracts/modules/sync` or `@shigomori/contracts/predicates/webUrl`. All schemas are also exported from one barrel, `@shigomori/contracts/schemas`. Inside this package, imports are relative and include the `.ts` extension.

The package's only runtime dependencies are `effect` and `semver`, and it imports nothing from the app so every side can compile it. Release versions are parsed with `semver` ([`src/releaseVersions.ts`](src/releaseVersions.ts), which adds prerelease channel handling).

[`fixtures/`](fixtures/) stores the JSON payloads each schema module accepts, produces, and refuses, one file per module, preventing a schema rewrite from silently changing wire or on-disk formats. [`test/fixtures.test.ts`](test/fixtures.test.ts) verifies them (`pnpm run check:contracts` from the repo root).

## Wire samples

Wire protocols between two builds are versioned in parts ([`src/protocol.ts`](src/protocol.ts)) so devices on different releases can stay linked and lose access only to modules that changed.

The core covers what every link requires: the greeting and byte channels ([`src/modules/link.ts`](src/modules/link.ts)), frame encoding, and the failure union (`CallFailureSchema`). Its version is `CORE_VERSION`. Two builds on different core versions cannot link at all: a host's listener refuses a dialer's hello for any core version other than its own, and the dialer determines which side is older from the refusal.

Every other module called across builds declares a version in its `defineContract`. This covers both modules a remote peer can reach and modules the terminal `sm` calls on its own machine's app. A host's welcome message includes the version of every module it serves. The dialing end compares those versions against its own (`outdatedModules` in [`src/link.ts`](src/link.ts)) and refuses any call to a mismatched module before sending it, failing with a `ModuleOutdatedError` that names the module, the device on the older build, and the device on the newer build. Pushes from an outdated module are never requested. Because the dialing end initiates every call, view, and push over a link, it is the single place where version mismatches are refused.

Two module groups have special versioning rules: `mirror` and `sync` share `MIRROR_VERSION` because mirroring relies on `sync` calls and both change together. `account` and `sharing` use the core's version because their pushes keep peer permissions up to date during a session, so they must work between any two builds that can link.

`fixtures/wire/<module>.v<version>.json` stores one encoded sample for every part sent by each versioned call in a module: an invoke's payload and result, a push's payload, and a view's payload and value. [`test/wire.test.ts`](test/wire.test.ts) verifies that every call has its samples and that each sample decodes and re-encodes back to the exact same value. If a schema change makes this build unable to read what an older build of the same version sends, that test fails. Fixing that requires bumping the module's version and replacing its samples file with one for the new version. When multiple modules share a changed schema, every affected module fails and must bump its version.

[`fixtures/wire/local.json`](fixtures/wire/local.json) stores samples for calls exchanged only between processes from the same build: `client` modules exchanged between a window and its own build's shell (excluding any remote calls), and unversioned modules such as `session` exchanged between a host and the shell that spawned it. These samples are edited in place.

Wire samples verify one direction: that this build can read what the version's samples contain. The reverse direction, ensuring an older build of the same version can read everything this build sends, must be checked in code review:

- No bump: adding a new call (an older build rejects an unknown call with a defect for that call alone), or adding a new optional field to a plain struct or a `loose` schema (an older build either drops it or preserves it as received).
- Bump the module version: any change that an older build would decode and reject or misread. Examples include adding a field to a `strict` schema (`strict` rejects unknown keys), removing or renaming a field or call, narrowing a type, or adding a new literal or union member.
- Bump the core version: changing the hello handshake or byte channels, adding a new error to `CallFailureSchema` (older builds cannot decode it), or changing the frame encoding.

The core version stays still, because bumping it cuts off every device on an older release until that device is updated manually. The hello payload must keep its shape because a build on another core version reads it before refusing the connection. The welcome payload is a plain struct, so new fields can be added to it. Send any new failure kind as a `RemoteCallError` with a `code` until a core bump is needed anyway.

To bump a module, increment its version, `git mv` its samples file to the new version's filename, and run `wire-fixtures`. Bumping the core follows the same process using `link.v<version>.json`.

If no build has been cut with a given version yet, edit its samples file in place without bumping the version, since no shipped build exists that expects the old bytes. Once a build ships with that version, the compatibility rules above apply. Because calls to a module at a different version are never sent, a field that a version makes optional is optional for its meaning, never for compatibility with an older peer.

`pnpm -F @shigomori/contracts wire-fixtures` generates a schema-derived sample for every part missing one, prompts for a manual sample when schema refinements leave nothing to derive automatically, and removes samples for calls and parts that no longer exist. It never overwrites existing samples and formats files to match the repo (oxfmt), keeping diffs limited to added or removed samples. It writes nothing if a bumped version's samples file has not yet been moved to its new filename. [`test/wire.test.ts`](test/wire.test.ts) also fails if a samples file does not match any module's current version, or if a channel appears twice in one file (a duplicate key that `JSON.parse` would silently hide).

# cli

The terminal `sm`: the `effect/cli` entrypoint over the engine, compiled with Bun.

- [`src/main.ts`](src/main.ts): the command tree over Bun's platform. [`src/engine.ts`](src/engine.ts) composes the engine's services, the store through `@effect/sql-sqlite-bun` (Bun's SQLite cannot load extensions, which the Node driver requires), and the filesystem helper (`nativefs`) beside the binary. A 2.x data dir is left to the app or to `doctor --fix` to migrate: until then, commands read it as v2 left it and refuse to modify it, and `agents event` does nothing (`unlessUnmigrated`).
- [`src/Control.ts`](src/Control.ts): the running app, reached over its loopback (`<dataDir>/loopback.json`) through a contract module's typed client (`control.client(loginContract).status()`), with each call on its own connection. The app owns the account and the links to other devices, so the cross-device verbs ([`src/Transfer.ts`](src/Transfer.ts)), `login`, `data`, and the guide's tools call into it, and moves or renames made while it runs go through it ([`src/commands/throughApp.ts`](src/commands/throughApp.ts)).
- [`src/here.ts`](src/here.ts): where a command runs among registered projects and which project it targets (`--project-id`, `-p`, or a positional argument, falling back to the project at the current working directory), through the engine's `Worktrees`. Terrier errors log as a warning there.
- [`src/commands/`](src/commands/): one module per verb group. A command decodes its input, calls the engine, and prints, per [`EFFECT.md`](../../EFFECT.md) section 1.
- [`src/help.ts`](src/help.ts): the help catalog of usage lines, each with its description and detail. Usage lines omit `-p <project>` (stated once in the prose), and a verb's `--json` shape goes in its detail as `{…}`. Before parsing, [`src/aliases.ts`](src/aliases.ts) expands aliases: after `sm wt`, any word that names none of `worktreesCommand`'s verbs is a worktree name passed to `switch`. [`src/argv.ts`](src/argv.ts) then reads the command line from each command's own flag definitions (flags anywhere and after any number of dashes, a valued flag taking the next argument whatever it is, the last of a repeated flag winning, a bare flag taking no value) and hands `effect/cli` one normalized form. A verb that allows extra positional arguments declares `rest` ([`src/here.ts`](src/here.ts)).
- [`src/menu.ts`](src/menu.ts), [`src/menuView.ts`](src/menuView.ts) (on ink), [`src/pickers.ts`](src/pickers.ts): the interactive menu a command opens when run in a terminal without naming a target. [`src/reporter.ts`](src/reporter.ts) and [`src/spinner.ts`](src/spinner.ts) show progress on stderr for long commands.
- [`src/stdinFd.ts`](src/stdinFd.ts): the fd number Bun's stdin reader claims, held from startup and released as the menu attaches, working around Bun losing a menu's first keystroke under load (its comment explains why).
- [`src/prompt.ts`](src/prompt.ts): a yes/no prompt on stderr, only at a terminal and never under `--json`.
- [`src/handOver.ts`](src/handOver.ts): hands the terminal to a child program (`run`'s script or `cd`'s subshell), forwards signals, and exits as the child did, dying of its signal (`Killed`, raised by [`src/main.ts`](src/main.ts) on the way out).
- [`src/build.ts`](src/build.ts): the flavor and version baked into this binary at build time.
- [`src/output.ts`](src/output.ts), [`src/errors.ts`](src/errors.ts): command output and errors. `--json` and `--verbose` are global anywhere up to `--`. Under `--json`, a failure prints the engine's error document (`errorDocument`) with `ok: false`. Otherwise it prints `sm: <message>` on stderr. A usage error exits 2, a command that has already printed its own output exits with its own code (`ExitCode`), a command whose child died of signal n exits 128+n (`Killed`), and any other failure exits 1.
- [`build.mts`](build.mts): `node build.mts [outfile] [--flavor=prod|dev|<test word>] [--version=<v>] [--arch=<x64|arm64>]` builds `dist/smd` (dev, the default), `dist/sm` (prod), or `dist/sm<word>` (a test flavor) as a Bun bytecode executable, signed ad hoc on macOS.
- The verbs, their flags, command-line parsing, refusal messages, exit codes, and `--json` output are a contract that [`skills/`](../../skills/), agent hooks, and user scripts depend on. Changing them, including adding a verb or flag, is the owner's call.
- Adding a verb: its command in [`src/commands/`](src/commands/), its line in the catalog ([`src/help.ts`](src/help.ts)), and its registration in [`src/main.ts`](src/main.ts), through `loaded` when it reads where it runs (which binds a calling agent session there first). A worktree verb is registered twice, under `worktreesCommand` and at the top level, since the prefix is optional.
- [`test/`](test/): the built binary on a sandbox data dir, checking a 2.x data dir left to the app and migrated by `doctor --fix`, which commits a land or an `rm --stack` keeps, and the shell config `sm shell uninstall` restores (`pnpm run check:cli` from the root, or one case with `pnpm -C packages/cli exec vitest run -t <name>`). It needs Bun, plus Go for the filesystem helper. It reuses the engine's sandbox ([`../engine/test/lib/sandbox.ts`](../engine/test/lib/sandbox.ts)): a home holding a 2.x data dir that only `doctor --fix` imports, so a case that needs the store migrated runs the app's startup migration first (`box.migrate`).

# cli

The terminal `sm`: the entrypoint on `effect/cli` over the engine, compiled with Bun.

- `src/main.ts`: the command tree over Bun's platform. `src/engine.ts` composes the engine's services, the store through `@effect/sql-sqlite-bun` (Bun's SQLite can't load extensions, which the node driver asks for), and the darwin helper (`macfs`) beside the binary. A 2.x data dir is left to the app to migrate, or to `doctor --fix`: until then the commands read it as v2 left it and refuse to change it, and `agents event` does nothing (`unlessUnmigrated`).
- `src/here.ts`: where a command runs among the projects, and the project it names (`--project-id`, `-p` or a positional, else the one at the cwd), through the engine's `Worktrees`. Terrier's trouble is a warning there.
- `src/commands/`: one module per verb group. A command decodes its input, calls the engine and prints, as `EFFECT.md` section 1 says.
- `src/help.ts`: the help, a catalog of usage lines, each with its description and detail. A usage line leaves out `-p <project>`, which the prose says once, and a verb's `--json` shape goes in its detail as `{…}`. `src/aliases.ts` folds the aliases before parsing: after `sm wt`, a word that names none of `worktreesCommand`'s verbs is a worktree's name, which `switch` takes. `src/argv.ts` then reads the command line (flags anywhere and after any number of dashes, a valued flag takes the next argument whatever it is, the last of a repeated flag wins, a bare flag takes no value) from each command's own flag definitions, and hands effect/cli one form of it. A verb that lets extra positionals be declares `rest` (`src/here.ts`).
- `src/menu.ts`, `src/menuView.ts` (on ink), `src/pickers.ts`: the menu a command opens when a person at a terminal runs it without naming its target. `src/reporter.ts` and `src/spinner.ts` are a long command's progress on stderr.
- `src/stdinFd.ts`: the fd number Bun's stdin reader gets, held from the start and given back as the menu attaches, a workaround for Bun losing a menu's first key under load (its comment says why). Bumping Bun means `pnpm -C packages/cli under-load` first: the at-a-terminal cases, typeahead's included, each run 60 more times with six busy loops beside them, eight rounds.
- `src/prompt.ts`: a yes or no asked on stderr, only at a terminal and never under `--json`.
- `src/handOver.ts`: a program given the terminal (`run`'s script, `cd`'s subshell): signals passed on, and sm ends as it did, dying of its signal (`Killed`, which `main.ts` raises on the way out).
- `src/build.ts`: the flavor and version the build gives this binary.
- `src/output.ts`, `src/errors.ts`: how a command prints. `--json` and `--verbose` are global wherever they sit up to a `--`. A failure under `--json` is the engine's error document (`errorDocument`) with `ok: false`, and a person gets `sm: <message>` on stderr. A usage error exits 2, any other 1, and a command that has said all it has to ends with its own code (`ExitCode`).
- `build.mts`: `node build.mts [outfile] [--flavor=prod|v3|dev] [--version=<v>]` builds `dist/smd` (dev, the default), `dist/smv3` (v3) or `dist/sm` (prod): Bun bytecode, ad hoc signed.
- The verbs, their flags, how a command line is read, what a refusal says, the exit codes and the `--json` output are a contract that `skills/`, agents' hooks and people's scripts depend on. `test/` holds the command line, the refusals and the exit codes to it, and the engine's tests the documents. A change to them, a new verb or flag included, is the owner's call.
- Adding a verb: its command in `src/commands/`, its line in the catalog (`src/help.ts`), and its registration in `src/main.ts`, through `loaded` when it reads where it runs, which binds a calling agent session there first. A worktree verb is registered twice, under `worktreesCommand` and at the top level, since the prefix is optional. The test runs every command the catalog names, in both forms, so a verb the catalog lists and the binary lacks fails it.
- `test/`: the built binary on a sandbox data dir: how a command line is refused, a person at a terminal, the shell's config and wrapper, and a script handed the terminal (`pnpm run check:cli` from the root, or one case with `pnpm -C packages/cli exec vitest run -t <name>`). It needs Bun, and Go for the darwin helper. Its sandbox is the engine's (`../engine/test/lib/sandbox.ts`): a home holding a 2.x data dir, which only `doctor --fix` imports, so a case that needs the store migrated has the app's start make it first (`box.migrate`).

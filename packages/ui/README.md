# ui

Presentational UI shared outside the app: views, the primitives they are built from, stylesheets, and the fixture world. Keeping them here lets the desktop window, web client, marketing site, and lab scene viewer render the same UI ([`app/DESIGN.md`](../../app/DESIGN.md), "Views and containers"). The app keeps its containers, hooks, store, and routes, and imports the rest from this package.

- [`src/views/`](src/views/): presentational views ([`app/DESIGN.md`](../../app/DESIGN.md), "Views and containers") grouped by area to mirror their containers under [`app/renderer/components`](../../app/renderer/components), along with view-only models. Each view takes data and callbacks and renders UI, while its container stays in the app.
- `src/views/*/build*.ts`, `gridModel.ts`, `projectListSections.ts`: row builders for the sidebar, inbox, home grid, and the palette. They are pure functions over the inputs produced by the app's hooks ([`src/lib/forest.ts`](src/lib/forest.ts) defines those input types), so scenes build rows the same way the app does.
- [`src/fixtures/`](src/fixtures/): the shared fixture world, containing a few devices with projects, worktrees, pull requests, changes, settings, and villagers. Scenes render this data directly, and the lab's fake host ([`app/lab/fake-host`](../../app/lab/fake-host)) serves it to the real app. Every worktree id is twelve hex digits, as required by contracts. No fixture repo has an icon, so every project renders with the app's letter tile: the app renders repo icons as `data:` URLs, which the marketing site's content security policy does not allow.
- [`src/scenes/`](src/scenes/): scenes showing snapshots of the app rendered by its views over the fixtures (listed in [`index.ts`](src/scenes/index.ts)). The marketing site renders them, and the lab's scene viewer renders one at a time at `/scenes.html?scene=<name>` on the desktop fake host's port ([`app/lab/fake-host/README.md`](../../app/lab/fake-host/README.md)).
- [`src/primitives/`](src/primitives/): core UI building blocks shared across views (button, input, tooltip, menus, modal shell), each carrying the `data-slot` attributes targeted by themes ([`app/DESIGN.md`](../../app/DESIGN.md)).
- [`src/hooks/`](src/hooks/): view-local hooks that manage component state, measure layout, or track time in the page (`useDirtyForm`, `useLauncherListEditor`, `useIsTruncated`, `useNow`, `useToday`, `useTypedText`, `useFaceColor`, `useShortPath`, `useRevealPicked`). None of them fetch data.
- [`src/lib/`](src/lib/): helpers and types used by views: `cn`, relative time formatting, file icons, fuzzy matching, human-readable device status text, villager voice text, a small external store, and the view types produced by the app's hooks and store (`BrowseListing`, `ScriptRunState`, `RemoteDeviceStatus`, `CommandAccess`, plus the device roster in [`deviceRoster.ts`](src/lib/deviceRoster.ts), which omits the host API carried by the app's own entries). [`devicePaths.ts`](src/lib/devicePaths.ts) and [`platform.ts`](src/lib/platform.ts) answer two of the platform questions ([`packages/engine/README.md`](../engine/README.md), "Which platform question to ask").
- [`src/root.tsx`](src/root.tsx): provides the window's theme root, which is the element carrying the theme classes, `data-palette`, and `data-shell` (the app's `#root` or a scene's frame). Overlays mount inside this root so they inherit the window's theme. The `data-shell` element is a CSS size container: its enclosing box sets its width and height, views lay out against those dimensions (`@min-*`, `cqh`), and a web shell narrower than 48rem switches to the phone layout ([`phone.css`](src/styles/phone.css)).
- [`src/outside.tsx`](src/outside.tsx): context for opening a web URL or revealing a filesystem path from a view. The app provides real implementations through the host at its root, while scenes fall back to no-op defaults.
- [`src/app-icons/`](src/app-icons/): launcher icons, which reveal buttons also read for the file manager icon.
- [`src/styles/`](src/styles/): shared stylesheets and PostCSS plugins. [`index.css`](src/styles/index.css) loads Tailwind, design tokens, and base rules, and imports the doubutsu overlay ([`doubutsu.css`](src/styles/doubutsu.css)), its palettes ([`palettes.css`](src/styles/palettes.css)), and the phone layout ([`phone.css`](src/styles/phone.css)). [`fonts.css`](src/styles/fonts.css) loads Zen Maru Gothic beside `index.css` rather than inside it, and [`fonts/`](src/styles/fonts/) holds the Nerd Font symbols and their license. [`insideTheRoot.ts`](src/styles/insideTheRoot.ts) is a PostCSS plugin that every build of the stylesheet runs via `css.postcss.plugins` in its Vite config: Tailwind emits its preflight, theme variables, and `@property` fallbacks globally on `html`, `:root`, and `*`, and this plugin scopes them to the theme root and its descendants so the stylesheet themes an embedded frame without affecting the surrounding page. Every build that loads `fonts.css` also runs [`woff2Only.ts`](src/styles/woff2Only.ts), which strips Fontsource's `.woff` fallbacks because no target browser requests them. Page-level styling remains the consumer's responsibility: the app's [`app.css`](../../app/renderer/app.css) styles its own `html`, `body`, and `#root`.

Consumers import modules by their path under `src/` with the file extension, such as `@shigomori/ui/primitives/button.tsx` or `@shigomori/ui/lib/utils.ts`. Inside this package, imports are relative and include the file extension.

This package declares its own runtime dependencies at the catalog's versions and keeps them in its own `node_modules`. Every build of the renderer tree deduplicates dependencies shared with the app so they resolve once from the app ([`app/vite.dedupe.ts`](../../app/vite.dedupe.ts)), ensuring the primitives and the app share a single React and a single Base UI instance. This package's stylesheet names this package's sources for Tailwind, and any stylesheet that imports it names its own sources (as in [`app/renderer/app.css`](../../app/renderer/app.css)).

## Adding a scene

A scene is a `<Name>Scene` component exported from its area's file under [`src/scenes/`](src/scenes/) that renders views over the fixtures using `noop` for callbacks. Each area file starts with a comment explaining what that area depicts, and each scene has a one-line comment describing what it shows. Register the scene in [`src/scenes/index.ts`](src/scenes/index.ts) under a camelCase name with its dimensions: `...DESKTOP` or `...PHONE` for a full window framed by `windowShell()` ([`src/scenes/frame.tsx`](src/scenes/frame.tsx)), or an explicit `[width, height]` for a standalone part drawn with no window around it. Comments in [`src/fixtures/fixtures.ts`](src/fixtures/fixtures.ts) document which device, project, and worktree represent each state. For sidebars, use `SceneSidebar` ([`src/scenes/sidebar.tsx`](src/scenes/sidebar.tsx)), passing `open` to expand shigoto-no-mori's tree.

Scenes are server-rendered by React, so they omit anything a view only renders inside a client effect. For example, terminal panes use xterm, which initializes in a client effect, so `terminalParts` draws their tabs and headers around blank panes. Only full-window scenes can run live on the marketing site ([`marketing/README.md`](../../marketing/README.md), "The frames"), so a partial scene like that needs a static view to appear there. Likewise, menus and dialogs normally open inside portals that server rendering omits, so scenes render them open inline: `StaticMenu` ([`src/primitives/dropdown-menu.tsx`](src/primitives/dropdown-menu.tsx)) renders a menu's surface on its own, and the parts scenes (`sidebarParts`, `worktreePageParts`) hold those open menus.

# main

The shell (Electron's main process). It owns everything that requires Electron (windows, the menu, dialogs, the keychain, and the updater) and runs the host as its own utility process ([`host/README.md`](../host/README.md), "A process of its own"). Each window reaches its host over loopback like any other device, and the shell serves only the calls that belong to the machine the window runs on.

- [`index.ts`](index.ts): the shell's entry point and composition root. It builds the shell's runtime over its layer graph ([`shellLayer.ts`](shellLayer.ts)) and quits when the last window closes. [`flavor.ts`](flavor.ts) defines this build's flavor (prod, dev, or a test flavor) and its names.
- [`hostProcess.ts`](hostProcess.ts): manages the shell's host process and sits as the top layer of the shell's graph. It forks [`host/process/host.ts`](../host/process/host.ts) with the shell's startup facts, serves calls from the host back to the shell (`shellCalls`) over a port, forks the host again if it exits unexpectedly, and asks it to quit when the graph closes.
- [`preload.ts`](preload.ts), [`preloadPort.ts`](preloadPort.ts), [`argFlags.ts`](argFlags.ts): window startup wiring. The preload reads the facts main passes on argv (defined in [`argFlags.ts`](argFlags.ts), shared by both sides) and requests the port that carries the window's calls to its shell.
- [`ipc/`](ipc/): the shell's link to its windows ([`ShellLink.ts`](ipc/ShellLink.ts)) and [`modules/`](ipc/modules/), containing one handler table per client-scoped contract module (window, menu, dialogs, shell, nav, migration, account, client config, releases, guide), each routing its calls to the module that owns them.
- [`electron/`](electron/): modules that need Electron: windows, the menu, deep links, the account, migration progress, Clerk's bridge and its tokens, the updater, liveness (the login item and crash recovery), the live half of nuke, and the log file.
- Adding a menu item ([`electron/menu.ts`](electron/menu.ts)): an item handled by a window sends a push to the focused window via `clickBroadcast(<contract>, "<push>", <payload>)`, with the push declared in the client module (`nav`, `window`) and listened for in the renderer. An item handled by the shell itself uses a plain `click`. Labels use title case to match macOS conventions ("Add Project…", "New Window"), ending with an ellipsis when the item asks for more input first.
- [`core/`](core/): shell logic that runs without Electron: the account's default device icon, the guide, keychain reset, liveness rate limits, host supervision ([`host/`](core/host/): the watchdog, the restart ledger, busy asks, and the prompt that follows them), startup after a nuke, and the shell's own JSON files ([`files/`](core/files/): files written synchronously on shutdown, and the rest on `FileSystem`).

The shell reads the data dir: [`index.ts`](index.ts) locates it (`initDataDir`) before building the menu or forking the host, and modules here read it through `@shared/paths`, which both processes compile. Most of the shell is plain Electron code (the menu, windows, deep links). [`EFFECT.md`](../../EFFECT.md) covers the Effect parts here: the layer graph ([`shellLayer.ts`](shellLayer.ts)), the services (`ClerkTokens`, `ShellLink`), and the handlers.
